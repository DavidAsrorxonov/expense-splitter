# Query plans

Generated by `npm run plans` against a scratch database populated by `npm run seed`, with `DATABASE_PATH` set to the same temporary file for both commands. The application database is not used.

These plans describe index usage on the small seed dataset, not production-scale timing. No new index was needed for the three Phase 4 queries.

## Active members of a group

```sql
SELECT * FROM members WHERE group_id = ? AND archived_at IS NULL
```

```text
SEARCH members USING INDEX idx_members_group_name_active (group_id=?)
```

## Expense list, newest first

```sql
SELECT * FROM expenses WHERE group_id = ? AND archived_at IS NULL ORDER BY spent_on DESC
```

```text
SEARCH expenses USING INDEX idx_expenses_group_spent_on (group_id=?)
```

## Monthly totals

```sql
SELECT strftime('%Y-%m', spent_on) AS month, SUM(amount_minor) FROM expenses WHERE group_id = ? AND archived_at IS NULL GROUP BY month
```

```text
SEARCH expenses USING INDEX idx_expenses_group_spent_on (group_id=?)
USE TEMP B-TREE FOR GROUP BY
```

SEARCH e USING INTEGER PRIMARY KEY (rowid=?)

## Full-text expense search

```sql
SELECT e.id, e.group_id, e.paid_by, e.amount_minor, e.note, e.spent_on, e.created_at, e.archived_at FROM expenses_fts JOIN expenses e ON e.id = expenses_fts.rowid WHERE expenses_fts MATCH ? AND e.group_id = ? AND (? = 1 OR e.archived_at IS NULL) ORDER BY bm25(expenses_fts), e.spent_on DESC, e.id DESC LIMIT ?
```

```text
SCAN expenses_fts VIRTUAL TABLE INDEX 0:M1
SEARCH e USING INTEGER PRIMARY KEY (rowid=?)
USE TEMP B-TREE FOR ORDER BY
```

Parameters: MATCH `"gro"*`, the seeded group ID, includeArchived = 0, limit = 50. The virtual-table scan uses the FTS MATCH index (`0:M1`), then looks up matching expenses by primary key. The temporary B-tree sorts matches by relevance, date, and ID; this is not a full scan of the expenses table.

## Archived expenses, newest first

```sql
SELECT id, group_id, paid_by, amount_minor, note, spent_on, created_at, archived_at FROM expenses WHERE group_id = ? AND archived_at IS NOT NULL ORDER BY spent_on DESC, id DESC
```

```text
SEARCH expenses USING INDEX idx_expenses_group_spent_on (group_id=?)
```

Uses idx_expenses_group_spent_on to select the group and return newest-first rows, filtering archived_at within that group. No additional index is indicated by this plan.

## All splits for a group

```sql
SELECT s.expense_id, s.member_id, s.share_minor FROM splits s JOIN expenses e ON e.id = s.expense_id WHERE e.group_id = ? ORDER BY s.expense_id, s.member_id
```

```text
SEARCH e USING COVERING INDEX idx_expenses_group_spent_on (group_id=?)
SEARCH s USING INDEX sqlite_autoindex_splits_1 (expense_id=?)
USE TEMP B-TREE FOR ORDER BY
```

Uses the covering group/date index to find expenses, then the splits composite primary-key index to find their shares. The temporary B-tree orders the result by expense and member; neither table requires a full scan for this query.
